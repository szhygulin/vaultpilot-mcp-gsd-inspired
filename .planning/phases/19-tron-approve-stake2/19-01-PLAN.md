<objective>
Ship `prepare_tron_token_approve` (TRON-PREP-05) + `prepare_tron_revoke_approval` (TRON-W-03) with a shared `prepareTronApproveInternal` helper enforcing byte-identity by construction (D-01). Extend `src/config/contracts.ts` with the `KNOWN_SPENDERS_TRON` sub-table (TRON-W-08). Pin Fixture Tron-19-A hardcoded `0x...` literal anchor. Surgically widen `src/tools/preview_send.ts` TRON branch with an approve/revoke arm placed BEFORE the existing Layer 0.5 + Layer 0.7 guards so the new handles reach the device with the correct selector (`0x095ea7b3`), the correct PREPARE RECEIPT template, the conditional `⚠ UNLIMITED APPROVAL` block, and the LEDGER NOTICE (TRON) blind-sign defense.

Purpose: TRC-20 approve is the LOAD-BEARING entry point for every TRON DeFi flow shipping in Phase 20+ (SunSwap, LiFi). Without the byte-identity invariant + `⚠ UNLIMITED APPROVAL` surfacing, an attacker who tampers with the agent's revoke call could substitute `approve(attacker, MAX_UINT256)` and the user wouldn't see the difference unless they read the on-device clear-sign value byte-for-byte. The shared helper makes drift impossible by construction; the fixture makes regression impossible at the test layer. The `preview_send` arm is the bridge: without it, every approve/revoke handle is structurally blocked by the existing Phase 18 TRC-20-transfer-only branch (hard guards at lines 1258 + 1281 + 1337 + 1363), `payloadFingerprint` re-check at send time never runs, and TRON-PREP-05 is undeliverable. The arm is additive — the existing `trc20-transfer` and `native-transfer` branches stay byte-identical pre/post.

Output: 4 new src files (`tron-approve.ts` + 2 tools + the contracts.ts extension as a single new sibling sub-table block) + 5 new test files (fixture file + protocol tests + tool tests + contracts.ts table test + preview-send approve arm test) + APPEND-ONLY templates in `blocks-tron.ts` + additive widening of `handle-store.ts` `TronInstructionSummary` union with 2 new kinds (`"trc20-approve"`, `"trc20-revoke"`) + ADDITIVE arm in `src/tools/preview_send.ts` TRON branch + `PreparedTxTron.kind` literal-union extension with no new value (approve reuses `kind: "trc20"` since it's a TriggerSmartContract — same dispatch shape as Phase 18 TRC-20 transfer; the discriminator in `TronInstructionSummary` carries the semantic distinction).
