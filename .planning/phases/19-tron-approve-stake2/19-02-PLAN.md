<objective>
Ship `prepare_tron_stake_freeze` + `prepare_tron_stake_unfreeze` + `prepare_tron_withdraw_expire_unfreeze` (TRON-W-04 + TRON-W-05) using TRON Stake 2.0 Protobuf contracts (`FreezeBalanceV2Contract` / `UnfreezeBalanceV2Contract` / `WithdrawExpireUnfreezeContract`). Surface the 14-day waiting period as informational in CHECKS PERFORMED (D-04a); enforce early-withdrawal refusal via the existing Layer 0.7 simulation gate (D-04b). Pin Fixture Tron-19-B hardcoded literal anchor.

Purpose: Stake 2.0 is the on-going protocol; Stake 1.0 is deprecated by TRON network as of `java-tron 4.6.0`. Using the wrong builder (`transactionBuilder.freezeBalance` vs `transactionBuilder.freezeBalanceV2`) silently produces a Stake-1.0 Protobuf contract type that the TRON network REJECTS at broadcast — too late for the user to recover gracefully. The fixture + grep regression makes Stake-1.0 contamination impossible at the test layer; the simulation gate makes early-withdrawal refusal cheap (no server-side time-tracker per D-04c).

Output: 1 new protocol file (`tron-stake.ts`) + 3 new tools + 5 new test files + ADDITIVE widening of `handle-store.ts` (`PreparedTxTron.kind` extended with 3 new values; `TronInstructionSummary` extended with 3 new kinds) + ADDITIVE templates in `blocks-tron.ts` + ADDITIVE caller-side skip in `canonical-dispatch-tron.ts` for Protobuf-native Stake 2.0 kinds + ADDITIVE TRON arms in `preview_send.ts` / `send_transaction.ts` / `get_tx_verification.ts` (asymmetric Layer 0.7 — freeze/unfreeze advisory, withdraw-expire mandatory refusal).
