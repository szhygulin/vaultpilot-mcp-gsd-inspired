<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → MCP | `preview_send` / `send_transaction` args (`handle`, `previewToken`, `userDecision`) are untrusted. |
| MCP handle store → preview/send | The stored `PreparedTxBtc` canonical artifact is the binding the drift gates check. |
| MCP → Ledger device | `signBtcPsbt` crosses to the device; the device is the only trusted display. |
| MCP → Esplora HTTP | The finalized raw tx is broadcast across this boundary via `POST /tx`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-13 | Tampering | PSBT serialization tampering between prepare and send | mitigate | `preview_send` (Layer 1) and `send_transaction` (Layer 3) recompute the fingerprint from the STORED CANONICAL ARTIFACT (unsigned tx hex + ordered prevouts), not the re-parsable PSBT; any byte change in the selected inputs/outputs diverges the fingerprint → `PAYLOAD_FINGERPRINT_DRIFT` refusal (Pitfall 5). |
| T-23-14 | Tampering | Per-input BIP-143/341 sighash drift | mitigate | `previewSendBtcBranch` recomputes every per-input sighash and asserts the concatenated fingerprint matches; a single drifted input fails the gate. The multi-hash `LEDGER BLIND-SIGN HASH` block surfaces every sighash for the user to compare against the device. |
| T-23-15 | Tampering | Mixed-input two-pass signing seam (one pass tampered between calls) | mitigate | `signBtcPsbt` finalizes via `Psbt.combine` then `finalizeAllInputs` + `extractTransaction`; the extracted raw tx is re-bindable — `send_transaction`'s Layer 3 fingerprint gate runs BEFORE the sign step, and the device independently re-derives each input's sighash, so a tampered pass produces a device-visible mismatch. `BTC_MIXED_INPUT_SIGN_FAILURE` surfaces a combine/finalize failure structurally. |
| T-23-16 | Tampering | Bypass of the send gate (missing previewToken / userDecision) | mitigate | `send_transaction`'s FROZEN three-gate region — `previewToken` + `userDecision: "send"` + fingerprint drift — is byte-untouched; the BTC arm reuses it (zero-diff assertion in `send-transaction.btc.test.ts`). |
| T-23-17 | Spoofing | Change-output redirection rendered as a normal send | mitigate | `knownAddressDerivations` includes the change address on every `signPsbtBuffer` call (Task 1) so the device marks it "change"; a redirected output renders as a "send" — device-visible (Pitfall 6). |
| T-23-18 | Information Disclosure | Esplora broadcast failure masked as success | mitigate | `broadcastTx` returns an explicit `{ kind: "rejected" | "error" }` arm mapped to `BROADCAST_FAILED` with the upstream message verbatim; never a silent success. |
| T-23-07 | Spoofing | Fabricated UTXOs / hostile Esplora endpoint | accept | Documented residual in SECURITY.md — Esplora endpoint trust is the operator's responsibility; the on-device input/output/fee review is the backstop. |
| T-23-SC | Tampering | npm installs | accept | No new packages in Phase 23 (RESEARCH §Package Legitimacy Audit). |
