<objective>
Build the `prepare_btc_send` MCP tool — the prepare half of the BTC trust pipeline. Wire coin selection → PSBT construction → per-input sighash → fingerprint → handle. Add the BTC block templates (`blocks-btc.ts`), widen `handle-store.ts` with `PreparedTxBtc`, add BTC error codes, and pin Fixture P (taproot) + Fixture Q (mixed).

Purpose: This is the user-facing entry point. The agent calls `prepare_btc_send`; the server BnB-selects UTXOs, builds a PSBT-v0, computes the per-input fingerprint, and stores an opaque handle. Segwit, taproot, and mixed-input sends all route through this one tool. Implements BTC-PSBT-01 and BTC-W-01.
Output: `prepare_btc_send.ts`, `blocks-btc.ts`, `handle-store.ts` union widening, BTC error codes, `register-all.ts` import, Fixtures P + Q.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → MCP | `prepare_btc_send` args (`to`, `sats`, `feeRate?`, `utxoOverride?`) are untrusted — the primary input-validation boundary. |
| MCP → Esplora HTTP | UTXO fetch crosses this boundary. |
| MCP handle store → preview/send | The stored `PreparedTxBtc` (canonical artifact) is the binding consumed by 23-04. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-08 | Tampering | Narrow agent-arg compromise (agent passes `to`/`sats` differing from user intent) | mitigate | PREPARE RECEIPT block emits the verbatim agent args read exclusively from `args` — no normalization. The user reviews the receipt before approving; defense-in-depth per CLAUDE.md. |
| T-23-09 | Tampering | Fee inflation via malicious `feeRate` | mitigate | `selectCoinsBnb` fee-rate sanity bounds (`BTC_FEE_RATE_OUT_OF_BOUNDS`) — `feeRate < 1` sat/vB or `> 10× highPriority` refused at prepare time (D-03). |
| T-23-10 | Information Disclosure | Invalid-input handling leaking state | mitigate | Input validation fires FIRST — an invalid `to` refuses before any Esplora fetch or `listAccounts` read (acceptance criterion asserts 0 fetch calls on the refusal path). |
| T-23-11 | Elevation of Privilege | Demo mode reaching real pairing state | mitigate | Demo-mode branch fires BEFORE `listAccounts({ chainFilter: "bitcoin" })`; `listAccounts` is never called in demo mode (test asserts 0 calls). |
| T-23-12 | Tampering | Fingerprint-drift between prepare and send | mitigate | `PreparedTxBtc` stores the canonical artifact (unsigned tx hex + ordered prevouts), NOT a re-parsable PSBT, so 23-04's recompute is byte-stable (Pitfall 5). |
| T-23-SC | Tampering | npm installs | accept | No new packages in Phase 23. |
</threat_model>
