<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → MCP | The agent supplies `{ to, sats, feeRate?, utxoOverride? }`; untrusted input parsed in 23-03 but the PSBT built here binds it. |
| MCP → Esplora HTTP | UTXO fetch + the change-chain scan cross this boundary; an attacker controlling the endpoint could supply fabricated UTXOs. |
| MCP → Ledger device | The device independently re-derives the change address; a wrong change address fails the device's "change" recognition (visible to the user). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-04 | Tampering | Fee inflation via a malicious `feeRate` | mitigate | `selectCoinsBnb` fee-rate sanity bounds — refuse `feeRate < 1` sat/vB and `> 10× highPriorityEstimate` (D-03, decimal-place-mistake defense). `feeSats` surfaced verbatim and approved on-device. |
| T-23-05 | Tampering | Change-output redirection | mitigate | The change address MUST be a real `m/8X'/0'/0'/1/k` derivation of the paired account (`change-index.ts` derives it from the on-chain xpub scan, not agent input). `buildBtcPsbt` populates the change output's BIP-32 derivation so the device marks it "change" — a redirected change output renders as a "send" and is visible to the user (Pitfall 6). |
| T-23-06 | Tampering | Dust-output donation / unrelayable tx | mitigate | Dust check on EVERY output: recipient below dust refuses; change below dust folds into the fee (D-07 / Pitfall 4 asymmetry). |
| T-23-07 | Spoofing | Fabricated UTXOs from a hostile Esplora endpoint | accept | Out of scope for Phase 23 — Esplora endpoint trust is the operator's responsibility (documented residual). The per-input sighash binding (23-01) + on-device input/output/fee review remain the backstop: the user reviews the actual selected inputs on the Ledger screen. |
| T-23-SC | Tampering | npm installs | accept | Phase 23 installs NO new packages; `coinselect` explicitly rejected in favor of the in-repo `btc-coin-select.ts` (RESEARCH OQ-2). Acceptance criterion asserts `grep -c "coinselect" package.json` == 0. |
</threat_model>
