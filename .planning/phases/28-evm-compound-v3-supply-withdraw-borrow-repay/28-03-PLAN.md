**Optimization note** — the second `readBaseToken` call in the refusal-message branch is intentional (it surfaces the actual base-asset address in the error message for agent self-correction). It only runs on the refusal path, so the cost is one extra RPC call ONLY when the agent picked the wrong tool. An alternative: cache `baseToken` from inside `deriveIntent` (mutate the return shape to `{ intent, baseToken }`). The cleaner shape — modify `deriveIntent` to return `{ intent: <label>, baseToken: Address }` — is the right design but ripples into Plan 28-02 callers. **Choice: keep `deriveIntent` returning the bare label; absorb the extra read only on refusal.** Document in PR body. (If review feedback prefers the cached shape, follow-up patch can refactor — both call sites change identically.)
