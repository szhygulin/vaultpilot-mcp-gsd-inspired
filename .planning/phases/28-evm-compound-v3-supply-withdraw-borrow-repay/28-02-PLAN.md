**Key intent-gate logic.** The `deriveIntent` helper (research § Greenfield, lines 763-781) is the ONE source of truth for the 4-arm intent label. Both prepare tools in THIS plan AND the 2 prepare tools in Plan 28-03 consume it; Plan 28-04 `preview_send` re-derives intent at preview time by calling the SAME helper (defense-in-depth — the prepare-tool gate can be bypassed by a handle reused under stale state; the preview re-check catches that case).

```typescript
// src/chains/compound-v3.ts — the helper
export async function deriveIntent(
  client: PublicClient,
  comet: Address,
  user: Address,
  selector: "supply" | "withdraw",
  asset: Address,
): Promise<"supply-collateral" | "repay-debt" | "withdraw-collateral" | "borrow"> {
  const baseToken = await _compoundChains.readBaseToken(client, comet);
  const isBase = getAddress(asset) === getAddress(baseToken);
  if (selector === "supply") {
    if (!isBase) return "supply-collateral";
    const debt = await _compoundChains.readBorrowBalance(client, comet, user);
    return debt > 0n ? "repay-debt" : "supply-collateral";
  }
  if (!isBase) return "withdraw-collateral";
  const supplied = await _compoundChains.readBaseBalance(client, comet, user);
  return supplied > 0n ? "withdraw-collateral" : "borrow";
}
```

The prepare tools in THIS plan check `if (intent === "repay-debt") return refusal({...hint: {tool: "prepare_compound_repay"}});` (supply tool) and `if (intent === "borrow") return refusal({...hint: {tool: "prepare_compound_borrow"}});` (withdraw tool).
