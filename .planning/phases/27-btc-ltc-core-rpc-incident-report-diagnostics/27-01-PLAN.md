    Exported function signature: `callBitcoinCoreRpc<T>(url: string | null, user: string | undefined, pass: string | undefined, method: string, params: unknown[]): Promise<BitcoinCoreRpcResult<T>>`.

    Behavior:
    - If `url === null` → return `{ kind: "not-configured" }` immediately (no fetch).
    - Build Authorization header ONLY when BOTH `user !== undefined` AND `pass !== undefined`: `"Basic " + Buffer.from(\`${user}:${pass}\`).toString("base64")`. When either is missing, omit the header (supports IP-allowlisted Core nodes per RESEARCH §Common Pitfalls §Pitfall 4).
    - POST with `Content-Type: application/json` and JSON-RPC body `{ jsonrpc: "1.0", id: "vaultpilot", method, params }`.
    - Wire timeout via `AbortController` + `setTimeout(controller.abort, BITCOIN_CORE_RPC_TIMEOUT_MS)`; `clearTimeout(timer)` in `finally` exactly like `lifi.ts:239`.
    - `resp.status === 429` → `{ kind: "rate-limited", message: "Bitcoin Core RPC rate-limited (429)" }`.
    - `!resp.ok` (any other non-2xx — Core uses HTTP 500 for application-level errors): try `await resp.json()`; if parseable and body.error has numeric `code` + string `message`, return `{ kind: "rpc-error", code, message }`. Otherwise return `{ kind: "rpc-error", code: resp.status, message: \`HTTP ${resp.status}\` }`. Do NOT misclassify as `network-error` (RESEARCH §Pitfall 2).

    - JSON parse failure on a 2xx → `{ kind: "network-error", message: "JSON parse error: <e.message>" }`.
    - Catch arm: `e?.name === "AbortError"` → `{ kind: "network-error", message: "Bitcoin Core RPC timeout (10000ms)" }`. Else → `{ kind: "network-error", message: "Bitcoin Core RPC unreachable: <e.message>" }`.
