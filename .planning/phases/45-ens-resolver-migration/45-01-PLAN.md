# Phase 45 / Plan 45-01 — ENS resolver migration off the compat shim

## Objective

Migrate `src/ens/resolver.ts` off the legacy `chains/ethereum.ts` compat
shim onto the multi-chain registry (`getChainClient(1)`), and migrate the
existing `test/ens-resolver.test.ts` to mock the registry. Do NOT touch
`src/tools/send_transaction.ts` (whole-file FROZEN per Phase 42) and do NOT
delete `src/chains/ethereum.ts` (still imported by the FROZEN
send_transaction). Partially advances Deferred Backlog DB-2 — removes one
of the shim's two importers.

## Context / Research

See `45-CONTEXT.md` (boundary + the resolved fork — **Option (b-minimal)**)
and `45-RESEARCH.md` (corrected importer/symbol facts, the whole-file
FROZEN boundary, the registry replacement symbol, ENS test impact,
validation architecture).

**Headline guarantee (first-class success criterion):
`git diff origin/main -- src/tools/send_transaction.ts` stays EMPTY. The
FROZEN signing file is not touched. The ENS resolver migrates; the shim is
kept for its one remaining (FROZEN) importer.**

**Corrections to the originating brief, baked into this plan:**
- Both shim importers pull `getEthereumClient` (not different symbols; no

## Threat model (ASVS L2)

The trust boundary is the Ledger screen; everything left of it can be
compromised. This phase touches a module adjacent to the signing path, so
the threat model centres on NOT perturbing the FROZEN signing file or the
ENS resolution semantics.

| Threat (STRIDE) | Vector | Mitigation in this plan |
|-----------------|--------|-------------------------|
| **Tampering** with the signing gate | A "cleanup" edit silently alters the byte-frozen `send_transaction.ts` | The file is NOT modified; `git diff origin/main -- src/tools/send_transaction.ts` EMPTY is a hard success criterion (task 45-01-3). Same gate class as Phase 42. (ASVS V14.2 — build/CI integrity.) |
| **Tampering** via wrong-chain client | Resolver wired to a non-mainnet client → ENS reads hit the wrong chain | `getChainClient(1)` pins mainnet (same as the shim's `getEthereumClient`); the migrated test asserts forward/reverse behaviour. (ASVS V5 — input integrity.) |
| **DoS** via ENS regression | Dropped `normalize()`/`null`-mapping breaks resolution | Behaviour preserved; the existing two test cases guard it. |
| **Elevation / surface creep** | Adding a new module path or new export | Pure swap of one import + two call sites; no new symbols, endpoints, or credentials. Shim deletion explicitly deferred (no attempt to unfreeze the signing file). (ASVS V1.1 — minimise attack surface.) |

No private key material crosses any boundary. No new network endpoints, no
new credentials, no new external input shapes. ENS reads were already a
mainnet RPC read before and after.
