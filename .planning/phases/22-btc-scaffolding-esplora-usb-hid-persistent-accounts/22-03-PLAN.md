    `scanXpub(xpub: string, scriptType: "p2wpkh" | "p2tr"): Promise<{ totalConfirmedSats: bigint; addressesScanned: number; activeAddresses: Array<{ index: number; address: string; confirmedBalanceSats: bigint }> }>` algorithm:
    1. Cache hit check (key: `${xpub}:${scriptType}`) — return cached result if not expired
    2. `const node = bip32.fromBase58(xpub)` — parse account-level xpub
    3. Loop with index `i` starting at 0; `consecutiveEmpty = 0`; `totalConfirmedSats = 0n`; `activeAddresses = []`
    4. In each batch of SCAN_CONCURRENCY=5 indices: derive child node `node.derive(0).derive(i)` (external-chain change=0), compute address via `payments.p2wpkh({ pubkey: childNode.publicKey, network: networks.bitcoin })` for p2wpkh OR `payments.p2tr({ internalPubkey: childNode.publicKey.slice(1, 33), network: networks.bitcoin })` for p2tr (taproot internal pubkey is x-only, drop first byte of compressed pubkey per BIP-340; cf. bitcoinjs-lib taproot docs). Fan out 5 parallel `fetchAddressInfo(address)` calls
    5. Per response: if combined `chain_stats.tx_count + mempool_stats.tx_count === 0` (NOT just chain_stats — RESEARCH §Plan 22-03 risks) → `consecutiveEmpty++`; else `consecutiveEmpty = 0`, accumulate balance, push to activeAddresses
    6. Terminate when `consecutiveEmpty >= BIP44_GAP_LIMIT` (20)
    7. Cache result with expiry `Date.now() + SCAN_TTL_MS`
    8. Return aggregate

    Anti-pattern (RESEARCH §Pitfall 4 + §Plan 22-03 risks): do NOT stop at first unused (`consecutiveEmpty` counter MUST be 20 CONSECUTIVE empties). Comment naming this is mandatory in source.
