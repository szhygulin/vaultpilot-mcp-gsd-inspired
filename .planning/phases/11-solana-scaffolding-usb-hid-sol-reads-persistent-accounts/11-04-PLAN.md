1. **`src/tools/pair_solana_ledger.ts` (new)** — mirror `pair_ledger_live.ts:99-210` body shape:

   - **Imports**: `registerTool` from `../tools/index.js`; `getDemoMode` / demo-state from `../demo/state.js`; `fetchSolanaAddress`, `LedgerDeviceNotConnectedError`, `LedgerSolanaAppNotOpenError`, `DEFAULT_SOLANA_DERIVATION_PATH`, `APPROVAL_TIMEOUT_MS` from `../wallet/ledger-solana-transport.js`; `saveAccount` from `../wallet/non-evm-account-store.js`; `log` from diagnostics.

   - **`VERIFY_ON_DEVICE_SOLANA_TEMPLATE` constant** (top-of-file, single source of truth — mirror `pair_ledger_live.ts:65-75`):
     ```
     VERIFY ON DEVICE
     ────────────────
     Address: {ADDRESS}
     Slot:    #{DERIVATION_PATH_LAST_INDEX}  (derivation path: 44'/501'/<{DERIVATION_PATH_LAST_INDEX}>')
     
     Open the Solana app on your Ledger. The address shown above MUST match
     the address displayed on the device screen byte-for-byte. If anything
     differs, do NOT approve.
     ```
     Two placeholders: `{ADDRESS}` (full base58); `{DERIVATION_PATH_LAST_INDEX}` (e.g. `0` for `"44'/501'/0'"`).

   - **DESCRIPTION** (agent routing prompt per CLAUDE.md ≥ 100 chars):
     "Open the Ledger Solana app over USB-HID, fetch the Solana base58 address from the configured derivation slot (default 44'/501'/0' — Ledger Live default), and persist the pairing for restart-safe `get_solana_status` reads. Use this when the user wants to read or (in Phase 12+) sign Solana transactions. Do NOT use this in demo mode — refuses with DEMO_MODE_REFUSED. Returns the address verbatim plus a VERIFY-ON-DEVICE block the user MUST match against the Ledger screen byte-for-byte. The persistent cache holds public-address + derivation-slot only; no key material crosses any boundary."

   - **INPUT_SCHEMA**: `{}` for Phase 11 (single-path default). Future v2.0.x patch can add `path?: string` (additive, non-breaking).

   - **Handler body (in order)**:
     1. **Demo-mode FIRST refusal** (mirror `pair_ledger_live.ts:102-114`):
        ```
        if (isDemoMode()) {
          return errEnvelope("DEMO_MODE_REFUSED", "pair_solana_ledger is not available in demo mode. ...");
        }
        ```
     2. **60s budget race**:
        ```
        const result = await Promise.race([
          fetchSolanaAddress(DEFAULT_SOLANA_DERIVATION_PATH),
          new Promise<never>((_, reject) =>
            setTimeout(() => reject(new ApprovalTimeoutError()), APPROVAL_TIMEOUT_MS)
          ),
        ]);
        ```
     3. **Persist via `saveAccount`**:
        ```
        const record = {
          chain: "solana" as const,
          address: result.address,
          derivationPath: DEFAULT_SOLANA_DERIVATION_PATH,
          pairedAt: new Date().toISOString(),
        };
        saveAccount(record);
        ```
     4. **Build VERIFY-ON-DEVICE block** by substituting `{ADDRESS}` and `{DERIVATION_PATH_LAST_INDEX}` (the `0` from `"44'/501'/0'"`).
     5. **Response envelope** (mirror `pair_ledger_live.ts` shape): `{ content: [{ type: "text", text: <VERIFY-ON-DEVICE block> }], structuredContent: { address, derivationPath, pairedAt, appVersion } }`. Note: `derivationPath` IS exposed on the pair-tool response (user just paired, they know their slot); the shoulder-surfing scrub applies to `list_paired_non_evm_accounts` only.

   - **Error mapping** (mirror `pair_ledger_live.ts:200-208`):
     - `LedgerDeviceNotConnectedError` → `LEDGER_NOT_CONNECTED`
     - `LedgerSolanaAppNotOpenError` → `SOLANA_APP_NOT_OPEN`
     - `ApprovalTimeoutError` → `APPROVAL_TIMEOUT`
     - Ledger APDU error 0x6985 (`UserRefusedOnDevice` / status code) → `USER_REJECTED`
     - Anything else → `INTERNAL_ERROR` with the original error message scrubbed of any PII patterns.

2. **`src/tools/get_solana_status.ts` (new)** — mirror `get_ledger_status.ts` end-to-end:
   - **DESCRIPTION** (agent routing prompt): "Returns the Solana Ledger pairing status: { paired: false } if no Solana account is in the persistent cache; { paired: true, address, derivationPath, rpcEndpoint, staleAccountWarning? } otherwise. Use this BEFORE any Solana read tool to confirm pairing. staleAccountWarning surfaces when pairedAt is older than 30 days — user should re-pair via pair_solana_ledger to confirm the device is still the same one."
   - **INPUT_SCHEMA**: `{}`.
   - **Handler**:
     - `const records = listAccounts({ chainFilter: "solana" });`
     - If empty, return `{ paired: false }`.

     - Compute `rpcEndpoint` via `_solanaRegistry.getResolvedRpcUrl()` (NOT `getSolanaRpcUrl()` — the resolved URL surfaces the actual endpoint in use, including public-RPC fallback).
     - Build response: `{ paired: true, address, derivationPath, rpcEndpoint, pairedAt, staleAccountWarning? }`. **Note**: `derivationPath` IS surfaced here (the user explicitly asked for their own pairing status — they can see their own slot index). The shoulder-surfing defense applies to `list_paired_non_evm_accounts` (which iterates and could be exfiltrated across chains).
