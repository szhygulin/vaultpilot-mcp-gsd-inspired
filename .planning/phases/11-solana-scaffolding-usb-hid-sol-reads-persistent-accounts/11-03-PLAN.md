[CITED: LedgerHQ/ledger-live PR [#10351](https://github.com/LedgerHQ/ledger-live/pull/10351/files) — Ledger Live mode `solanaBip44` = 3-level; mode `solanaBip44Change` = 4-level Phantom-compat.] Multi-path UX (Phantom-compat `"44'/501'/0'/0'"`) DEFERRED. - **CRITICAL — Ledger Solana `getAddress()` return shape**: returns `{ address: Buffer }` (32-byte Ed25519 pubkey), NOT a base58 string. All callers MUST apply `bs58.encode(buf)`. Doc-comment names this drift between docs and types so future maintainers don't trust the doc-string blindly.
- **NodeNext + ESM default-export drift** (research § Topic 2): the Ledger packages' `lib-es/.d.ts` exports `default` only; under TS5+ NodeNext the typed default class sometimes fails the constructor check. Use the compile-clean pattern:
  ```
  import TransportNodeHidModule from "@ledgerhq/hw-transport-node-hid";
  import SolanaAppModule from "@ledgerhq/hw-app-solana";
  const TransportNodeHid = (TransportNodeHidModule as any).default ?? TransportNodeHidModule;
  const SolanaApp = (SolanaAppModule as any).default ?? SolanaAppModule;
  ```
- **Device cleanup invariant**: `transport.close()` MUST be called after every pubkey fetch. USB-HID device handles leak otherwise (research § Topic 2 lines 121-127); the next `pair_solana_ledger` call would fail with "device busy". Tests assert `close()` invocation in both happy + error paths.
- **`disconnected` field**: `transport.disconnected: boolean` is public; once `true`, every subsequent APDU exchange throws `DisconnectedDevice` from `@ledgerhq/errors`. Phase 11 reads don't sign — but Plan 11-04's pair tool must `close()` after pubkey fetch.

   - **Spy-affordance indirection** (CLAUDE.md non-negotiable):
     ```
     export const _transport = {
       isSupported: () => TransportNodeHid.isSupported(),
       list: () => TransportNodeHid.list(),
       open: (path: string | null) => TransportNodeHid.open(path),
       buildSolanaApp: (t: any) => new SolanaApp(t),
     };
     ```
     All internal calls go through `_transport.X` (NOT `TransportNodeHid.open(...)` direct) so `vi.spyOn(_transport, "open")` intercepts. The wrapper functions in `_transport` are the test seam.

   - **`openTransport()`** — opens a fresh transport per call (NOT singleton — USB-HID device handles must be closed after each operation per research § Topic 2):
     ```
     export async function openTransport(): Promise<any> {
       const supported = await _transport.isSupported();
       if (!supported) throw new LedgerDeviceNotConnectedError();
       const devices = await _transport.list();
       if (!devices || devices.length === 0) throw new LedgerDeviceNotConnectedError();
       return _transport.open(null);  // null = first available device
     }
     ```

   - **`fetchSolanaAddress(derivationPath = DEFAULT_SOLANA_DERIVATION_PATH): Promise<{ address: string; rawPubkey: Buffer; appVersion: string }>`** — the load-bearing function consumed by Plan 11-04's pair handler. Try/finally ensures `transport.close()` always runs:
     ```
     export async function fetchSolanaAddress(derivationPath = DEFAULT_SOLANA_DERIVATION_PATH) {
       const transport = await openTransport();
       try {
         const app = _transport.buildSolanaApp(transport);
         let cfg;
         try {
           cfg = await app.getAppConfiguration();
         } catch (e) {
           throw new LedgerSolanaAppNotOpenError();
         }
         const { address: rawPubkey } = await app.getAddress(derivationPath);
         // CRITICAL: rawPubkey is a Buffer (32-byte Ed25519 pubkey), NOT a base58 string
         const address = bs58.encode(rawPubkey);
         return { address, rawPubkey, appVersion: cfg.version ?? "unknown" };
       } finally {
         await transport.close();  // ALWAYS — USB-HID handle leaks otherwise
       }
     }
     ```

   - **No eager-init export** — the transport is opened on-demand by `pair_solana_ledger`. Persistence lives in Plan 11-01's account store; the transport itself is per-process.
