<objective>
Extend the existing Phase-32 sandwich-MEV gate (fixed 50bps default / >2% price-impact refusal, Ethereum-only) to per-chain thresholds via a new `src/config/sandwich-mev-thresholds.ts` SOT, add a dedicated `SANDWICH_MEV_REFUSED` errorCode, and migrate BOTH the EVM (Uniswap) and TRON (SunSwap) sandwich refusals to it. Curve stays gate-free by design (CHECKS-PERFORMED note update only). This closes MEV-01 and the v2.6 milestone (SECURITY.md per-L2 MEV section + v2.6 close-out).

Purpose: A swap on Polygon (public Bor mempool, high MEV-searcher activity) carries materially higher sandwich risk than the same swap on Arbitrum/Optimism/Base (private centralized-sequencer mempools). A single global 2% bar is therefore both too loose for Polygon and too tight for the private-sequencer L2s. Per-chain calibration aligns the refusal bar with each chain's actual mempool exposure, and a consistent `SANDWICH_MEV_REFUSED` errorCode gives agents one refusal contract across all chains.

Output: New per-chain SOT + resolver + env override; `SANDWICH_MEV_REFUSED` errorCode; migrated Uniswap (per-chain threshold + errorcode + enriched refusal detail) and SunSwap (errorcode only) gates; Curve gate-free note + regression; get_uniswap_quote warning tracking the ethereum SOT bar; SECURITY.md per-L2 section + v2.6 close-out. Pure swap-tool + config + errorcode + docs work — NO trust-pipeline (FROZEN) files touched.
</objective>
