<objective>
The four Tier-1 bridge facet decoders + their unit tests, plus registration into the
Plan 39-01 registry. Each decoder extracts the final-recipient field from one bridge's EVM
calldata and returns it ALREADY-NORMALIZED into its comparable form, via a NEVER-throws
discriminated union (WR-02). This is the correctness core of Phase 39.

Purpose: Recipient NORMALIZATION is the highest-risk detail of this phase. The decoder returns
`finalRecipient` in the SAME normalized form the user-supplied recipient will be normalized to at
preview_send time, so the Layer 0.6 equality assertion is a plain string compare. A blanket
`.toLowerCase()` is a CORRECTNESS BUG for Solana (base58 is case-sensitive) and for bytes32 (last-20-bytes
truncation produces a nonsense EVM-looking value for a 32-byte Solana pubkey).

Output:
- `across-v3.ts` — recipient is plain EVM `address` → `getAddress()` (EIP-55). Simplest.
- `near-omnibridge.ts` — recipient is ABI `string` (NEAR account id) → `.toLowerCase().trim()`.
- `wormhole.ts` — recipient is `bytes32`; branch on `recipientChain`: EVM dest → last-20-bytes `getAddress()`; Solana (chain 1) → `bs58.encode(full 32 bytes)`; other non-EVM → `{ kind: "error" }`.
- `mayan-swift.ts` — two selectors share OrderParams; `destAddr` (bytes32) at tuple index 7; branch on `destChainId`: leading-12-zero-bytes → EVM `getAddress()`, else Solana `bs58.encode`.
- `index.ts` — TIER1_DECODERS map populated with all five selectors.
</objective>

## Trust Boundaries

| Boundary | Description |
