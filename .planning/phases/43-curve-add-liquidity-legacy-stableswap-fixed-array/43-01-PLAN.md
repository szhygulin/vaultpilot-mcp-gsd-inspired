Lift the Phase 34 / 34-03 deferral: `prepare_curve_add_liquidity` currently hard-refuses
`abiVersion: "legacy"` pools (`prepare_curve_add_liquidity.ts:176-191`). Add the legacy
dispatch arm so the one legacy pool in the curated registry — stETH/ETH
(`0xDC24316b9AE028F1497c275EB9192a3Ea0f67022`, 2 coins) — can add liquidity through the same
prepare → preview → send trust pipeline. This is the direct mirror, for `add_liquidity`, of the
per-`abiVersion` dispatch `prepare_curve_swap` already ships for `exchange`.

The work is one cohesive additive change across tightly-coupled files (ABI shelf, protocol
encoder/decoder/selector, the one tool, its preview decode block, and four test files that all
change together). Single plan per the research primary recommendation.

Purpose: Curve LP completeness for the only legacy pool registered — the stETH/ETH ETH-in deposit
path that the stable_ng arm cannot encode (fixed `uint256[2]` vs dynamic `uint256[]`, `@payable`).
Output: legacy ABI + encoder/decoder/selector + tool dispatch arm + preview decode case +
Fixtures CRV-D/CRV-E + extended regressions across 4 existing test files.

ALL ABI shapes + both new selectors are RESEARCH-VERIFIED (StableSwapSTETH.vy + Etherscan + viem,
three independent sources agree byte-for-byte). Do NOT re-derive them. The selectors below are
literals to pin via byte-identity test, NOT facts to recompute as a planning step.
