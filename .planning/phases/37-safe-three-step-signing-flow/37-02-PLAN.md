<objective>
Land the off-chain co-sign + signature-publish surface that completes the three-step Safe flow's signature-collection phase. `prepare_safe_tx_approve` is the agent's "another owner already proposed; I want to add my signature" entry point. `submit_safe_tx_signature` is the publish step that ECDSA-recovers locally before POSTing to the Safe Tx Service. Neither tool produces an on-chain transaction — both are off-chain coordination steps that gate the eventual `prepare_safe_tx_execute` (Plan 37-03).

Purpose: signature-collection is the load-bearing trust surface between propose and execute. Locally ECDSA-recovering BEFORE the POST defends against narrow agent compromise (the agent claims a signature came from wallet X but it came from Y); the on-chain `getOwners()` cross-check defends against stale Tx Service state (the agent fetches an "owner" list that no longer reflects on-chain truth after a recent `removeOwner`); the handle-store transition closes the prepare→sent state-machine arc that started in Plan 37-01.

Output: 1 client method extension, 2 new tool files, 2 new test files, 1 register-all extension, ~12-15 new client tests + ~25 new tool tests. </objective>
