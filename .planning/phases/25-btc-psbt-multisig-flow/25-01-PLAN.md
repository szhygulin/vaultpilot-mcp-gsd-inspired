<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → register_btc_multisig_wallet | Untrusted descriptor string + wallet name cross here |
| server → btc-multisig.json on disk | Registry file holds wallet metadata; readable only by the owning user |
| server → Esplora HTTP | Untrusted balance/UTXO data returned from a third-party indexer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Tampering | register_btc_multisig_wallet descriptor input | mitigate | parseWshSortedMulti validates the BIP-380/381 form, M/N bounds, and `/**` suffix; malformed input → MULTISIG_DESCRIPTOR_INVALID before any persistence |
| T-25-02 | Spoofing | Wrong multisig address shown to user (descriptor differs from co-signers' view) | mitigate | First 5 derived P2WSH addresses surfaced in a VERIFY-ON-DEVICE block; user verifies against co-signers before use |
| T-25-03 | Information Disclosure | btc-multisig.json registry file readable by other users | mitigate | writeAtomic writes at mode 0o600; ensureStorageDirWithPerms locks the directory |
| T-25-04 | Tampering | Esplora returns malformed/malicious balance or UTXO data | mitigate | Read-only path; no signing decision derives from Esplora here; values surfaced for display, never used to build a tx in this plan |
| T-25-05 | Denial of Service | Corrupt btc-multisig.json blocks all multisig tools | accept | loadFromDisk drops invalid entries and never deletes the file (forensic option); a fully-corrupt file degrades to an empty registry, not a crash |
| T-25-SC | Tampering | npm install of @ledgerhq/ledger-bitcoin / @bitcoinerlab/descriptors | mitigate | Both packages [OK] in RESEARCH.md Package Legitimacy Audit (official Ledger + established community lib); no install task in this plan — `@bitcoinerlab/descriptors-core` is already transitively installed; `@ledgerhq/ledger-bitcoin` install is gated in Plan 25-03 |
</threat_model>
