**Locked research findings affecting this plan:**

- **SDK choice — `createTransferCheckedInstruction`** (RESEARCH Topic 6, DON'T HAND-ROLL row): preferred over `createTransferInstruction` (deprecated). TransferChecked passes mint + decimals AS instruction args, so the on-chain SPL program verifies decimals against the mint AND verifies the source ATA holds the named mint. Defense-in-depth — drift between agent-claimed mint and actual source-ATA mint → tx fails at simulation (consumed by Plan 12-04 DF-4 gate).
- **ATA derivation server-side** (Pitfall 3 from RESEARCH): the agent passes a Solana wallet address as the SPL `to`; the server derives `destinationAta = getAssociatedTokenAddress(mint, recipientWallet)`. PREPARE RECEIPT surfaces the wallet (user-facing) with the derived ATA disclosed as a sub-line (analog to EVM Phase 6 where `to` is the recipient and `tokenAddress` is the contract).
- **Conditional ATA-creation** (Pitfall 4 from RESEARCH): pre-flight `connection.getAccountInfo(destinationAta)` — when `null`, prepend `createAssociatedTokenAccountInstruction(payer=feePayer, associatedToken=destinationAta, owner=recipientPubkey, mint)` as instruction[0]. Sender pays rent (~0.002 SOL); PREPARE RECEIPT carries `{ATA_NOTICE}` slot rendering "This tx will also create the recipient's ${TOKEN_SYMBOL} account (rent: ~0.002 SOL paid by you)".
- **`userInputType: "sol"` (NOT "ata")** (RESEARCH Topic 2 + orchestrator override): Phase 12 SPL v1.x scope locks `userInputType: "sol"` only — the `to` arg is a Solana wallet address, the server derives the ATA. The "ata"-direct path defers. This decision is consumed at Ledger signTransaction time (Plan 12-04 `signSolanaTransaction`); Plan 12-03 stores the agent's verbatim wallet `to` in `PrepareArgs` for that downstream call.
- **Sender-DEPENDENT fingerprint** (research Topic 1 + integration-test Plan 12-05): SPL fingerprints differ across personas because `sourceAta = getAssociatedTokenAddress(mint, senderPubkey)` derives from sender. Persona-cycle integration test (Plan 12-05) asserts per-persona-deterministic + cross-persona-distinct (mirror Phase 7 Aave `T-INTEGRATION-FROM-DRIFT-2` shape per orchestrator + CONTEXT.md line 26).
- **Don't hand-roll** (RESEARCH): NEVER manually compute the ATA via `findProgramAddressSync(seeds, programId)` — the seed order (`owner_pubkey, TOKEN_PROGRAM_ID, mint`) is easy to get wrong. Always use `getAssociatedTokenAddress(mint, owner)`.
- **Decimal-string at the boundary** (CLAUDE.md): `amount` arg crosses as HUMAN UNITS (e.g. `"100.5"` for 100.5 USDC). Server resolves `decimals` from the mint metadata and calls `parseSolanaAmountStrict(args.amount, decimals)` → raw `bigint` units.
- **PrepareArgs verbatim** (PREP-02): agent's raw `to` + `mint` + `amount` strings stored AS-IS; PREPARE RECEIPT reads from THAT verbatim copy; NEVER base58-normalized form.

1. **`src/protocols/solana-spl.ts` (new)** — mirror `src/protocols/erc20.ts` shape:
   - Import `Connection`, `Transaction`, `TransactionInstruction`, `PublicKey` from `@solana/web3.js`.
   - Import `createTransferCheckedInstruction`, `createAssociatedTokenAccountInstruction`, `getAssociatedTokenAddress`, `TOKEN_PROGRAM_ID`, `ASSOCIATED_TOKEN_PROGRAM_ID` from `@solana/spl-token` (Phase 11 already wired).
   - Export `async function deriveAtaForOwner(owner: PublicKey, mint: PublicKey): Promise<PublicKey>` — wraps `getAssociatedTokenAddress(mint, owner)` (Pitfall 3 — never hand-roll the seed order).
   - Export `async function maybeAppendCreateAtaInstruction(input: { connection: Connection; payer: PublicKey; destinationAta: PublicKey; recipientOwner: PublicKey; mint: PublicKey }): Promise<{ instructions: TransactionInstruction[]; created: boolean }>`:
     - `const accountInfo = await connection.getAccountInfo(destinationAta);`
     - `if (accountInfo === null)` → return `{ instructions: [createAssociatedTokenAccountInstruction(payer, destinationAta, recipientOwner, mint)], created: true }`.
     - Else → return `{ instructions: [], created: false }`.
     - Defensive — wraps the `getAccountInfo` call so RPC failure surfaces as `BROADCAST_FAILED` upstream; never throws past the tool handler.
   - Export `encodeSplTransferChecked(input: { source: PublicKey; mint: PublicKey; destination: PublicKey; owner: PublicKey; amount: bigint; decimals: number }): TransactionInstruction` — wraps `createTransferCheckedInstruction(input.source, input.mint, input.destination, input.owner, input.amount, input.decimals)`. RESEARCH Topic 6 explicit: TransferChecked (NOT Transfer) — on-chain decimals + mint verification is the load-bearing defense-in-depth.
   - Export `async function buildSplTransferTx(input: { connection: Connection; from: PublicKey; toWallet: PublicKey; mint: PublicKey; amount: bigint; decimals: number; recentBlockhash: string }): Promise<{ transaction: Transaction; messageBytes: Uint8Array; programIds: string[]; instructionSummary: SolanaInstructionSummary[]; createDestAta: boolean; sourceAta: string; destAta: string }>`:
     - `const sourceAta = await deriveAtaForOwner(input.from, input.mint);`
     - `const destAta = await deriveAtaForOwner(input.toWallet, input.mint);`
     - `const { instructions: maybeCreate, created } = await maybeAppendCreateAtaInstruction({ connection, payer: input.from, destinationAta: destAta, recipientOwner: input.toWallet, mint: input.mint });`
     - `const transferIx = encodeSplTransferChecked({ source: sourceAta, mint: input.mint, destination: destAta, owner: input.from, amount: input.amount, decimals: input.decimals });`
     - `const tx = new Transaction({ recentBlockhash: input.recentBlockhash, feePayer: input.from });`
     - `tx.add(...maybeCreate, transferIx);` — createATA goes FIRST when needed (Pitfall 4); transferChecked second.
     - `const messageBytes = new Uint8Array(tx.serializeMessage());`
     - `const programIds = [TOKEN_PROGRAM_ID.toBase58(), ...(created ? [ASSOCIATED_TOKEN_PROGRAM_ID.toBase58()] : [])];`
     - `const instructionSummary: SolanaInstructionSummary[] = [{ kind: "spl-transfer-checked", mint: input.mint.toBase58(), from: input.from.toBase58(), to: input.toWallet.toBase58(), sourceAta: sourceAta.toBase58(), destAta: destAta.toBase58(), amount: input.amount, decimals: input.decimals, createDestAta: created }];`
     - Return all fields. `createDestAta` consumed by the PREPARE RECEIPT `{ATA_NOTICE}` slot rendering.
   - Export `decodeSplCall(instruction: TransactionInstruction): { kind: "transfer-checked"; source: string; mint: string; destination: string; amount: bigint; decimals: number } | { kind: "create-ata"; payer: string; destinationAta: string; owner: string; mint: string } | { kind: "unknown" }` — defensive decoder. Inspects `programId` + first byte of `data`. Used by Plan 12-04 preview_send DECODED ARGS surfacing. Never throws.
   - Export `_solanaSpl = { deriveAtaForOwner, maybeAppendCreateAtaInstruction, encodeSplTransferChecked, buildSplTransferTx, decodeSplCall }` ESM spy-affordance.

          await buildSplTransferTx({ connection: getConnection(), from: feePayer, toWallet: new PublicKey(args.to), mint: new PublicKey(args.mint), amount, decimals, recentBlockhash: blockhash });

        Wrap `buildSplTransferTx` in try/catch — RPC failure (e.g. `getAccountInfo` timeout) → `BROADCAST_FAILED` with cause.
     8. **Create handle**:
        ```typescript
        createHandle({
          tx: { txType: "solana", messageBytes, feePayer: feePayer.toBase58(), recentBlockhash: blockhash, programIds, instructionSummary },
          args: { to: args.to, mint: args.mint, amount: args.amount, recentBlockhash: blockhash }, // VERBATIM agent strings + pinned blockhash

        });
        ```
     9. **PREPARE RECEIPT** — substitute from `PREPARE_RECEIPT_SOLANA_SPL_TEMPLATE` (Plan 12-01 ships):
        - `{TO}` ← `args.to` (verbatim wallet address).
        - `{MINT}` ← `args.mint` (verbatim base58).
        - `{AMOUNT}` ← `args.amount` (verbatim human-units string).
        - `{RECENT_BLOCKHASH}` ← pinned blockhash.
        - `{ATA_NOTICE}` ← conditional: when `createDestAta === true`, render `"NOTICE: recipient does not yet hold this token. This tx will also create their token account (rent ~0.002 SOL, paid by sender)."`. When `false`, render empty string.
     10. **Response shape** — `{ content: [{ type: "text", text: <PREPARE RECEIPT block> }], structuredContent: { handle, to: args.to, mint: args.mint, amount: args.amount, decimals, recentBlockhash: blockhash, payloadFingerprint, txType: "solana", sourceAta, destAta, createDestAta } }`.
