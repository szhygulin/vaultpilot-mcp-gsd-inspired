## `src/security/skill-integrity.ts` shape (LOCKED — mirror of `src/diagnostics/notice.ts` dedup pattern + RESEARCH § Topic 3 sketch lines 149-220)

```typescript
// src/security/skill-integrity.ts (NEW Phase 9 Plan 09-02)
//
// Lazy SHA-256 integrity probe for the companion vaultpilot-preflight skill.
// Fires on the FIRST tool dispatch of the session (NOT at server boot — boot-time
// IO blocks the MCP initialize handshake per Phase 5 retro). Mirror of
// `src/diagnostics/update-check.ts::runUpdateCheckOnce` lazy pattern.
//
// Dedup-per-session NOTICE emission mirrors `src/diagnostics/notice.ts::consumeAutoDemoNotice`
// — `noticeEmitted` flag set BEFORE returning the template (Pitfall 4 race-mitigation).
//
// EXPECTED_SKILL_SHA256 is the SOT for the SHA pin. Computed at Plan 09-02
// execute time via fixpoint algorithm against `09-01-SKILL-TEMPLATE.md`.
// Format-fanout-sentinel: this constant is the single hit in src/; grep returns 1.

import { createHash } from "node:crypto";
import { readFile } from "node:fs/promises";
import { homedir } from "node:os";
import { join } from "node:path";

import {
  VAULTPILOT_NOTICE_TEMPLATE_MISSING,
  VAULTPILOT_NOTICE_TEMPLATE_TAMPERED,
} from "../signing/blocks.js";

// EXPECTED_SKILL_SHA256 — single-SOT constant. Updated as a coordinated bump
// with the vaultpilot-preflight-skill v1.3.x sister-repo tag release.
// Plan 09-02's execute-time fixpoint algorithm computed this hex against
// .planning/phases/09-hardening-skill-and-verification-tools/09-01-SKILL-TEMPLATE.md.
export const EXPECTED_SKILL_SHA256 = "<computed-at-execute-time-fixpoint>";

const PROBE_PATHS = [
  () => join(homedir(), ".claude", "skills", "vaultpilot-preflight", "SKILL.md"),
  () => join(process.cwd(), ".claude", "skills", "vaultpilot-preflight", "SKILL.md"),
] as const;

export type SkillIntegrityState =
  | { kind: "ok"; path: string; sha256: string }
  | { kind: "missing"; pathsProbed: string[] }
  | { kind: "tampered"; path: string; computed: string; expected: string };

let cachedState: SkillIntegrityState | null = null;
let noticeEmitted = false;

export async function checkSkillIntegrity(): Promise<SkillIntegrityState> {
  if (cachedState !== null) return cachedState;
  const probed: string[] = [];
  for (const pathFn of PROBE_PATHS) {
    const path = pathFn();
    probed.push(path);
    try {
      const content = await readFile(path);
      const computed = createHash("sha256").update(content).digest("hex");
      cachedState =
        computed === EXPECTED_SKILL_SHA256
          ? { kind: "ok", path, sha256: computed }
          : { kind: "tampered", path, computed, expected: EXPECTED_SKILL_SHA256 };
      return cachedState;
    } catch {
      // ENOENT — try next probe path
    }
  }
  cachedState = { kind: "missing", pathsProbed: probed };
  return cachedState;
}

export const _skillIntegrity = { checkSkillIntegrity };  // ESM spy-affordance per CLAUDE.md Convention

export function consumeSkillIntegrityNotice(state: SkillIntegrityState): string | null {
  if (noticeEmitted) return null;
  if (state.kind === "ok") return null;
  noticeEmitted = true;  // SET BEFORE RETURN — Pitfall 4 race-mitigation per src/diagnostics/notice.ts:51
  if (state.kind === "missing") {
    return VAULTPILOT_NOTICE_TEMPLATE_MISSING.replace(
      "{PATHS}",
      state.pathsProbed.join("\n    "),
    );
  }
  return VAULTPILOT_NOTICE_TEMPLATE_TAMPERED
    .replace("{PATH}", state.path)
    .replace("{COMPUTED}", state.computed)
    .replace("{EXPECTED}", state.expected);
}

export function _resetSkillIntegrityForTesting(): void {
  cachedState = null;
  noticeEmitted = false;
}
```

## EXPECTED_SKILL_SHA256 fixpoint algorithm (LOAD-BEARING)

The literal text `EXPECTED_SKILL_SHA256_PLACEHOLDER` (31 chars) is replaced by a 64-char hex string. The byte-delta is identical across all occurrences (3 in template — Step 0 narrative occurrence + Step 0 backtick literal occurrence; 1 in README integrity-check section). The SHA changes between iterations BUT converges in 2 iterations because the byte-delta is fixed.

**Algorithm:**

```bash
TEMPLATE_PATH=".planning/phases/09-hardening-skill-and-verification-tools/09-01-SKILL-TEMPLATE.md"
SKILL_PATH="vaultpilot-preflight-skill/SKILL.md"      # outside main repo
README_PATH="vaultpilot-preflight-skill/README.md"    # outside main repo

# Iteration 1: compute SHA against PLACEHOLDER content.
SHA1=$(sha256sum "$TEMPLATE_PATH" | awk '{print $1}')
sed -i.bak "s/EXPECTED_SKILL_SHA256_PLACEHOLDER/$SHA1/g" "$TEMPLATE_PATH"
# Now $TEMPLATE_PATH has the SHA-of-placeholder, but the content has CHANGED
# (placeholder removed, hex added), so the new SHA differs from SHA1.

# Iteration 2: compute SHA against the substituted content.
SHA2=$(sha256sum "$TEMPLATE_PATH" | awk '{print $1}')
sed -i.bak "s/$SHA1/$SHA2/g" "$TEMPLATE_PATH"

# Iteration 3: confirm fixpoint reached (SHA3 should equal SHA2).
SHA3=$(sha256sum "$TEMPLATE_PATH" | awk '{print $1}')
if [ "$SHA3" != "$SHA2" ]; then
  echo "FIXPOINT NOT REACHED in 2 iterations — investigate"
  exit 1
fi

# Now $SHA2 is the fixpoint. Substitute everywhere.
EXPECTED_SHA="$SHA2"
echo "EXPECTED_SKILL_SHA256 = $EXPECTED_SHA"

# Substitute into src/security/skill-integrity.ts
sed -i.bak "s/<computed-at-execute-time-fixpoint>/$EXPECTED_SHA/g" src/security/skill-integrity.ts

# Substitute into sister-repo SKILL.md + README (out-of-codebase)
cd vaultpilot-preflight-skill
cp ../"$TEMPLATE_PATH" SKILL.md  # copy the FIXPOINT template
sed -i.bak "s/EXPECTED_SKILL_SHA256_PLACEHOLDER/$EXPECTED_SHA/g" README.md
# Verify sister-repo CI sha256.sh now passes locally:
bash test/sha256.sh
# Commit + force-tag-with-lease v1.3.0 (USER-CONFIRMED — sister-repo tag bump)
git add . && git commit -m "release: v1.3.0 SHA fixpoint substitution (closes 09-02 loop)"
git tag --force v1.3.0
git push origin main --tags --force-with-lease
```

**Why 2 iterations suffice:** after Iteration 1, the file content's "shape" is stable (same number of bytes; only the hex value changes between iterations). Each occurrence of the SHA appears in the same byte positions in the file. Iteration 2's SHA is computed against the file with `SHA1` substituted in. Iteration 3's SHA equals Iteration 2's SHA because the content is identical (we substituted SHA1→SHA2, but SHA2 is the SHA of the file with SHA1 in it; once we substitute SHA1→SHA2 the file changes again — wait, this is NOT a fixpoint).

**Correction — the algorithm above is WRONG.** Substituting `SHA1 → SHA2` changes the file content again, so Iteration 3's SHA will differ from SHA2. The actual fixpoint discipline is: **never embed the SHA in a file that's HASHED to produce the SHA.** The standard pattern is to embed the SHA only OUTSIDE the hashed file.

**Revised algorithm (CORRECT — embed SHA only OUTSIDE the hashed file):**

```bash
TEMPLATE_PATH=".planning/phases/09-hardening-skill-and-verification-tools/09-01-SKILL-TEMPLATE.md"

# Compute SHA against the PLACEHOLDER content — this is the "canonical" SHA.
# The file content stays AS-IS (placeholder remains in Step 0 narrative + README integrity-check).
# The MCP's EXPECTED_SKILL_SHA256 constant carries the SHA of the placeholder-state file.
EXPECTED_SHA=$(sha256sum "$TEMPLATE_PATH" | awk '{print $1}')
echo "EXPECTED_SKILL_SHA256 = $EXPECTED_SHA"

# Substitute into src/security/skill-integrity.ts ONLY (NOT into SKILL.md).
sed -i.bak "s/<computed-at-execute-time-fixpoint>/$EXPECTED_SHA/g" src/security/skill-integrity.ts

# Substitute into sister-repo README integrity-check section ONLY (NOT into sister-repo SKILL.md).
# The sister-repo SKILL.md retains the literal `EXPECTED_SKILL_SHA256_PLACEHOLDER` text in Step 0 —
# which IS what gets hashed. Users running `sha256sum SKILL.md` get the SAME hex that's in the MCP constant.
cd vaultpilot-preflight-skill
# Re-copy the (unchanged) template to ensure sister-repo SKILL.md is byte-identical to the planning-time SOT.
cp ../"$TEMPLATE_PATH" SKILL.md
# Substitute the placeholder in README integrity-check section.
sed -i.bak "s/EXPECTED_SKILL_SHA256_PLACEHOLDER/$EXPECTED_SHA/g" README.md
# Verify sister-repo CI sha256.sh now passes locally:
bash test/sha256.sh
git add . && git commit -m "release: v1.3.0 — substitute README EXPECTED_SKILL_SHA256 (closes 09-02 loop)"
git tag --force v1.3.0
git push origin main --tags --force-with-lease
```

**Net effect:** the SKILL.md retains `EXPECTED_SKILL_SHA256_PLACEHOLDER` in its body (Step 0 narrative + the backtick literal). The README documents the REAL hex. The MCP server pins the REAL hex. The Step 0 self-check in the skill: agent reads the SKILL.md, sees `EXPECTED_SKILL_SHA256 = \`EXPECTED_SKILL_SHA256_PLACEHOLDER\`` — that's the documented expected. Agent runs `sha256sum SKILL.md` to compute. Match expected to actual computed hex.

**Wait — Step 0 says "compare against `EXPECTED_SKILL_SHA256_PLACEHOLDER`". The agent will compare against the literal string `EXPECTED_SKILL_SHA256_PLACEHOLDER` (since that's what's in the Step 0 text), which is NEVER going to equal the computed SHA hex.** This is broken.

**Correct discipline (final):** Step 0 instructs the agent to compare against an EXTERNAL source of truth (the README's documented EXPECTED_SKILL_SHA256, OR the MCP server's `INSTRUCTIONS` field which pins the SHA). Rewrite Step 0 in `09-01-SKILL-TEMPLATE.md` accordingly:

```markdown
2. Look up the EXPECTED_SKILL_SHA256 from one of:
   - vaultpilot-mcp's MCP `initialize` response `instructions` field (pinned at server build time)
   - The sister repo's README.md "Expected SHA-256" line (kept in sync with the MCP pin)
3. Compare the computed SHA against the EXPECTED.
```

Plan 09-02's executor **MUST** edit `09-01-SKILL-TEMPLATE.md` to remove the SKILL-internal `EXPECTED_SKILL_SHA256 = ...` line in Step 0 (replace with the indirection above), then run the SIMPLE algorithm: compute SHA of the (now-stable) template once, substitute into `src/security/skill-integrity.ts` + sister-repo README. The SKILL.md itself never contains the SHA; the SHA lives in the MCP server + README only.

**Plan 09-02's executor is RESPONSIBLE for this Step 0 edit** as part of closing the loop. The Plan 09-01 deliverable shipped the placeholder-state Step 0 with the broken self-referential pattern; Plan 09-02 fixes it before the SHA gets pinned. Documented in PR body: "Step 0 self-reference resolved at Plan 09-02 by externalizing the EXPECTED SHA to the README + MCP `instructions` field; SKILL.md itself never contains the SHA, avoiding circular-hash."

**This is a deviation from Plan 09-01's spec** — but a load-bearing one. The deviation is recorded here as a planning-time correction; Plan 09-01 is unchanged (its placeholder-state release is the scaffolding; Plan 09-02 closes the loop including the Step 0 edit). The alternative (fixpoint algorithm against a self-referential file) does NOT converge for SHA-256 (cryptographic hash; the file content's SHA can't predict its own hash by construction).
