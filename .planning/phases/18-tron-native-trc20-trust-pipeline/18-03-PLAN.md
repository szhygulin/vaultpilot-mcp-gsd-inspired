**Locked research findings affecting this plan:**

- **Topic 8 LOAD-BEARING**: TRC-20 calldata is ABI-identical to ERC-20: selector `0xa9059cbb` + 32-byte left-padded address + 32-byte big-endian amount = 68 bytes total. tronweb's `transactionBuilder.triggerSmartContract` ABI-encodes the parameters internally; we pass `[{ type: "address", value: toBase58 }, { type: "uint256", value: amount.toString() }]` and tronweb wraps in TriggerSmartContract Protobuf with `owner_address` + `contract_address` + `data` fields.
- **Topic 3**: TRC-20 `feeLimit: 100_000_000` (100 TRX) is hardcoded per CONTEXT D-04a — sufficient for Phase 18's USDT/USDC/USDD/TUSD set. USDT-TRC20 transfer is ~31,895 energy at ~420 sun/energy = ~13.4 TRX of cost; 100 TRX is a generous cap. Phase 19+ may add user-controllable `feeLimit` if energy markets shift.
- **Topic 5 LOAD-BEARING**: Same `extendExpiration(tx, 900)` discipline as Plan 18-02.
- **Topic 7**: `PreparedTxTron` carries both `rawDataHex: string` AND `rawDataObject: unknown`. Plan 18-03 populates `contractAddress: args.tokenAddress` (base58) onto the handle so Plan 18-04's preview branch can dispatch the Layer 0.5 canonical-dispatch check.
- **Persona-cycle sender-dependence**: `owner_address` is a Protobuf field in `TriggerSmartContract`. Swap personas → `owner_address` bytes change → `raw_data_hex` changes → fingerprint differs. Defense-in-depth: ALSO check that the calldata's first arg (`to`) is invariant across personas while `owner_address` varies — confirms the bug per CONTEXT D-05b.

1. **`src/protocols/tron-trc20.ts` (new)** — encoder + decoder. Mirror `src/protocols/solana-spl.ts:60-407` shape (without ATA derivation):
   - Imports:
     - `TronWeb` type from `tronweb`.
     - `_tronRegistry` from `../chains/tron/registry.js`.
     - `parseTronAddress`, `formatTronAddress` from `../chains/tron/address.js`.
     - `TronInstructionSummary` from `../signing/handle-store.js`.
   - Export `interface TronTrc20EncodeResult { transaction: unknown; rawDataHex: string; rawDataBytes: Uint8Array; rawDataObject: unknown; refBlockBytes: string; refBlockHash: string; expiration: number; contractAddress: string; instructionSummary: TronInstructionSummary[] }`.
   - Export `async function encodeTronTrc20Transfer(input: { tronWeb: TronWeb; from: string; to: string; tokenAddress: string; amount: bigint; decimals: number }): Promise<TronTrc20EncodeResult>`:
     - Step 1: call `const result = await input.tronWeb.transactionBuilder.triggerSmartContract(input.tokenAddress, "transfer(address,uint256)", { feeLimit: 100_000_000, callValue: 0 }, [{ type: "address", value: input.to }, { type: "uint256", value: input.amount.toString() }], input.from);`
       - **`feeLimit: 100_000_000`** = 100 TRX hardcoded cap per RESEARCH §Topic 3 + CONTEXT D-11. USDT-TRC20 transfer fits well under this.
       - **`callValue: 0`** = no TRX value attached (this is a TRC-20 transfer, not a payable function).
       - **`amount.toString()`** — tronweb's parameter encoding accepts `uint256` as a decimal string; `bigint` would be silently truncated to `Number` on the SDK boundary. Per RESEARCH §Topic 1 boundary-discipline.
       - Verify `result.result?.result === true` AND `result.transaction !== undefined` — non-true result → throw `Error("triggerSmartContract build failed: " + JSON.stringify(result.result))`. Caller catches → `INTERNAL_ERROR` envelope.
     - Step 2: `let tx = result.transaction; tx = await input.tronWeb.transactionBuilder.extendExpiration(tx, 900);` — **CRITICAL per RESEARCH §Topic 5**. Same 15-min extension as Plan 18-02.
     - Step 3: extract `rawDataHex`, `rawDataBytes`, `rawDataObject` (same as Plan 18-02).
     - Step 4: extract `refBlockBytes`, `refBlockHash`, `expiration` (same as Plan 18-02).
     - Step 5: build `instructionSummary: TronInstructionSummary[] = [{ kind: "trc20-transfer", from: input.from, to: input.to, tokenAddress: input.tokenAddress, amount: input.amount, decimals: input.decimals }];`
     - Return tuple with `contractAddress: input.tokenAddress` (verbatim base58 — Plan 18-04 preview branch consumes for Layer 0.5 dispatch).
   - Export `type TronTrc20Decoded = { kind: "transfer"; from: string; to: string; tokenAddress: string; amount: bigint; selector: "0xa9059cbb" } | { kind: "unknown" };`.
   - Export `function decodeTronTrc20Call(transaction: { raw_data: { contract: Array<{ type: string; parameter: { value: { owner_address: string; contract_address: string; data: string; call_value?: number } } }> } }): TronTrc20Decoded`:
     - Defensive: `transaction.raw_data?.contract?.[0]` undefined → `{ kind: "unknown" }`.
     - Verify `transaction.raw_data.contract[0].type === "TriggerSmartContract"`; mismatch → `{ kind: "unknown" }`.
     - Extract `parameter.value.owner_address` (0x41-prefixed hex), `parameter.value.contract_address` (0x41-prefixed hex), `parameter.value.data` (hex string, no `0x` prefix per tronweb convention).
     - Verify `data.length >= 8 + 64 + 64 = 136 hex chars` (4-byte selector + 32-byte to + 32-byte amount = 68 bytes = 136 hex chars). Shorter → `{ kind: "unknown" }`.
     - Extract `selector = "0x" + data.slice(0, 8);`. Verify `selector === "0xa9059cbb"` (`transfer(address,uint256)`); mismatch → `{ kind: "unknown" }`.
     - Extract `to` from `data.slice(8 + 24, 8 + 64)` (last 20 bytes of the 32-byte address slot — ABI left-pads with zeros). Prepend `0x41` to get the TRON-form hex → `formatTronAddress(0x41 + to20byteHex)`.
     - Extract `amount = BigInt("0x" + data.slice(8 + 64, 8 + 128))`.
     - Convert `owner_address` + `contract_address` hex → base58 via `formatTronAddress`.
     - Return `{ kind: "transfer", from: base58From, to: base58To, tokenAddress: base58Contract, amount, selector: "0xa9059cbb" }`.
     - NEVER throws — any malformed input → `{ kind: "unknown" }`.
   - Export `_tronTrc20 = { encodeTronTrc20Transfer, decodeTronTrc20Call }` ESM spy-affordance.
   - Top-of-file comment: cite RESEARCH §Topic 8 (TRC-20 calldata is ABI-identical to ERC-20 — same selector `0xa9059cbb`, same arg encoding); note that the encoder NEVER inlines selector + arg encoding manually (tronweb handles it); the decoder DOES manually slice the data hex (no external decoder dep for the TriggerSmartContract envelope's `data` field).
