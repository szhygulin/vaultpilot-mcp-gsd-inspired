**Locked research findings affecting this plan:**

- **Topic 1**: tronweb's `transaction.raw_data_hex` is the canonical Protobuf preimage. **`Buffer.from(raw_data_hex, "hex")` produces the bytes input to `_tronFingerprint.computeTronPayloadFingerprint({ rawDataBytes })`.**
- **Topic 5 LOAD-BEARING**: tronweb's default `expiration` is `block_timestamp + 60_000ms` (60 seconds). Our handle TTL is 15 minutes. **Plan 18-02 MUST call `extendExpiration(tx, 900)` after `transactionBuilder.sendTrx` returns** so the expiration matches the handle TTL. Without this, a user who waits ~5min between prepare and send would broadcast an expired tx (`BROADCAST_FAILED: TRANSACTION_EXPIRATION_ERROR`).
- **Topic 6**: TRON address validation goes through `tronweb.utils.address.isAddress` (Phase 17 wiring); NEVER hand-roll base58check decoding.
- **Topic 7**: `PreparedTxTron` carries BOTH `rawDataHex: string` (canonical preimage source) AND `rawDataObject: unknown` (the original tronweb `transaction.raw_data` for Plan 18-04 broadcast envelope reconstruction). Plan 18-02 populates both at handle creation time.

1. **`src/protocols/tron-native.ts` (new)** — encoder + decoder + ref-block reader. Mirror `src/protocols/solana-system.ts:60-218` shape:
   - Import `TronWeb` type from `tronweb` (TRON SDK transit type — typed import).
   - Import `_tronRegistry` from `../chains/tron/registry.js` (ESM spy seam — never bare-import `getTronWeb`).
   - Import `parseTronAddress`, `formatTronAddress` from `../chains/tron/address.js` (Phase 17 helpers).
   - Import `TronInstructionSummary` from `../signing/handle-store.js`.
   - Export `interface TronNativeEncodeResult { transaction: unknown; rawDataHex: string; rawDataBytes: Uint8Array; rawDataObject: unknown; refBlockBytes: string; refBlockHash: string; expiration: number; instructionSummary: TronInstructionSummary[] }`.
   - Export `async function encodeTronTransfer(input: { tronWeb: TronWeb; from: string; to: string; sun: bigint }): Promise<TronNativeEncodeResult>`:
     - Step 1: `let tx = await input.tronWeb.transactionBuilder.sendTrx(input.to, Number(input.sun), input.from);` — tronweb takes `Number` for amount; we convert from bigint at this boundary. **Overflow guard at the conversion**: if `input.sun > Number.MAX_SAFE_INTEGER`, throw `RangeError("sun overflows MAX_SAFE_INTEGER — TRON max balance is ~9e15 sun ≈ 9 billion TRX; reject before tronweb truncates")`. Phase 17 RESEARCH §Topic 1 surfaced this Pitfall — tronweb's `sendTrx` takes `number`, not bigint. (Same boundary discipline as `getNativeBalance` in `src/chains/tron/tron-rpc-client.ts:107-113`.)
     - Step 2: `tx = await input.tronWeb.transactionBuilder.extendExpiration(tx, 900);` — **CRITICAL per RESEARCH §Topic 5**. Without this, tronweb's default 60s expiration produces a broadcast-time error for any handle older than ~60s. 900 seconds = 15 minutes = matches `HANDLE_TTL_MS`.
     - Step 3: extract `rawDataHex = tx.raw_data_hex;` + `rawDataBytes = new Uint8Array(Buffer.from(rawDataHex, "hex"));` + `rawDataObject = tx.raw_data;` (preserve the object for Plan 18-04 broadcast envelope reconstruction).
     - Step 4: extract `refBlockBytes = tx.raw_data.ref_block_bytes;` + `refBlockHash = tx.raw_data.ref_block_hash;` + `expiration = tx.raw_data.expiration;` (all directly from the tronweb object — no hand-rolling).
     - Step 5: build `instructionSummary: TronInstructionSummary[] = [{ kind: "native-transfer", from: input.from, to: input.to, sun: input.sun }];`.
     - Return the full tuple.
   - Export `type TronNativeDecoded = { kind: "transfer"; from: string; to: string; sun: bigint } | { kind: "unknown" };` — sibling of `SolanaSystemDecoded`.
   - Export `function decodeTronNativeCall(transaction: { raw_data: { contract: Array<{ type: string; parameter: { value: { owner_address: string; to_address: string; amount: number } } }> } }): TronNativeDecoded`:
     - Defensive: `transaction.raw_data?.contract?.[0]` undefined → `{ kind: "unknown" }`.
     - Verify `transaction.raw_data.contract[0].type === "TransferContract"`; mismatch → `{ kind: "unknown" }`.
     - Extract `parameter.value.owner_address` (0x41-prefixed hex), `parameter.value.to_address` (0x41-prefixed hex), `parameter.value.amount` (number).
     - Convert hex → base58 via `formatTronAddress(hex)` (the Phase 17 helper round-trips correctly).
     - Return `{ kind: "transfer", from: base58From, to: base58To, sun: BigInt(amountNumber) }`.
     - NEVER throws — malformed input returns `{ kind: "unknown" }`.
   - Export `_tronNative = { encodeTronTransfer, decodeTronNativeCall }` ESM spy-affordance.

   - Define tool schema:
     ```typescript
     const schema = z.object({
       to: z.string().min(34).max(34).describe("Recipient TRON address (base58check T-prefixed)."),
       sun: z.string().regex(/^[0-9]+(\.[0-9]+)?$/).describe("Amount in raw sun (10^6 sun = 1 TRX) as a decimal string. Pass `\"1000000\"` for 1 TRX. Do NOT pass decimal TRX — pass raw sun."),
     });
     ```
     - **NO `chain` field** — TRON is single-chain (mirror of Solana tool's no-chain shape per CONTEXT D-10).
     - **NO `expiration` user-facing arg** — handled internally via `extendExpiration(tx, 900)`.
   - Tool description (agent routing prompt — be precise; cite CLAUDE.md convention):
     > Prepare an unsigned native TRX transfer (TransferContract Protobuf) from the paired TRON Ledger account. Returns a handle the agent passes to preview_send before send_transaction. Use when the user wants to send native TRX. Do NOT use for TRC-20 transfers — that's `prepare_tron_trc20_send`. Do NOT use for staking / SunSwap / LiFi — those are Phase 19/20. `sun` is the amount in raw sun (10^6 sun = 1 TRX) as a decimal string — never pass human-readable TRX amounts (off-by-decimal is the most common user-facing bug class). Requires a paired TRON Ledger (call `pair_tron_ledger` first if `get_tron_status` shows `paired: false`). Returns `{ handle, chain: "tron", to, sun, refBlockBytes, refBlockHash, expiration, payloadFingerprint, prepareReceipt }`. In demo mode, succeeds against the active TRON persona address; `send_transaction` returns a simulation envelope instead of broadcasting. Failure modes: `WALLET_NOT_PAIRED` (real mode, no paired TRON account), `WRONG_MODE` (demo mode but no persona set), `INVALID_INPUT` (to/sun malformed or `to` not a valid base58check TRON address).
   - Handler logic:
     - Validate `to` via `tronweb.utils.address.isAddress(args.to)` → false → `INVALID_INPUT` envelope naming the field + the expected base58check shape.
     - Validate + parse `sun` via `parseTronAmountStrict(args.sun, 0, "u64")` → catch `InvalidAmountError` → `INVALID_INPUT` envelope naming the kind discriminator (`empty` / `format` / `fractional-overflow` / `u64-overflow`).
     - Resolve sender:
       - Demo mode (`getDemoState().mode === "demo"`): `from = getActivePersonaAddress("tron");` → `null` → `WRONG_MODE` envelope per Phase 5 pattern.
       - Real mode: `from = (await getActiveNonEvmAccount("tron"))?.address;` → undefined → `WALLET_NOT_PAIRED` envelope ("Pair your Ledger TRON app via `pair_tron_ledger` before preparing TRX transfers").
     - Get `tronWeb = _tronRegistry.getTronWeb();`.
     - Call `const encoded = await _tronNative.encodeTronTransfer({ tronWeb, from, to: args.to, sun });` → catch transport errors → `INTERNAL_ERROR` envelope.
     - Compute `payloadFingerprint = _tronFingerprint.computeTronPayloadFingerprint({ rawDataBytes: encoded.rawDataBytes });`
     - Build `PreparedTxTron` shape:
       ```typescript
       const tx: PreparedTxTron = {
         txType: "tron",
         chainId: 0,                // sentinel
         to: "0x0000000000000000000000000000000000000000",  // sentinel
         valueWei: 0n,              // sentinel
         data: "0x",                // sentinel
         rawDataHex: encoded.rawDataHex,
         rawDataObject: encoded.rawDataObject,
         refBlockBytes: encoded.refBlockBytes,
         refBlockHash: encoded.refBlockHash,
         expiration: encoded.expiration,
         kind: "native",
         instructionSummary: encoded.instructionSummary,
       };
       ```
     - Build `PrepareArgs` shape:
       ```typescript
       const prepareArgs: PrepareArgs = {
         to: args.to,                  // verbatim agent string
         valueWei: "0",                // sentinel for non-EVM
         sun: args.sun,                // verbatim agent string
         refBlockBytes: encoded.refBlockBytes,
         refBlockHash: encoded.refBlockHash,
         expiration: String(encoded.expiration),
       };
       ```
     - `const handle = createHandle({ args: prepareArgs, tx, payloadFingerprint });`
     - Build text response:
       ```typescript
       const prepareReceipt = PREPARE_RECEIPT_TRON_NATIVE_TEMPLATE
         .replace("{TO}", args.to)
         .replace("{SUN}", args.sun)
         .replace("{REF_BLOCK_BYTES}", encoded.refBlockBytes)
         .replace("{REF_BLOCK_HASH}", encoded.refBlockHash)
         .replace("{EXPIRATION}", String(encoded.expiration));
       const responseText = `${prepareReceipt}\n\nHandle: ${handle}\npayloadFingerprint: ${payloadFingerprint}\n\nNext step: pass this handle to preview_send.`;
       ```
     - Return `{ content: [{ type: "text", text: responseText }], structuredContent: { handle, chain: "tron", to: args.to, sun: args.sun, refBlockBytes: encoded.refBlockBytes, refBlockHash: encoded.refBlockHash, expiration: encoded.expiration, payloadFingerprint, prepareReceipt } }`.
   - Wrap entire handler in `try/catch` → unhandled errors → `INTERNAL_ERROR` envelope (Phase 4 catch-all discipline).
