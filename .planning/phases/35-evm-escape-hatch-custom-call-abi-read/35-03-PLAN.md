<objective>
Ship the `prepare_custom_call` MCP tool — the v2.4 milestone close-out. Three coordinated load-bearing surfaces:

1. **Schema gate** (`acknowledgeNonProtocolTarget: { const: true, type: "boolean" }`) at the JSON-Schema dispatch boundary — defeats `acknowledgeNonProtocolTarget: false` BEFORE the handler runs. Missing/false → structured refusal naming canonical alternatives via `lookupCanonicalAlternative(selector)`.

2. **Canonical-dispatch bypass** — `prepare_custom_call` writes `record.acknowledgeNonProtocolTarget = true` onto the handle. `preview_send` at the EVM dispatch site (lines ~792-814) short-circuits the refusal when this flag is set. The flag is set by `prepare_custom_call` ONLY — enforced by grep-guard test.

3. **`[WARN — NON-PROTOCOL TARGET]` block** — emitted byte-identically in BOTH `prepare_custom_call` response AND `preview_send` response. Drift between the two = tamper signal. Best-effort ABI-decode at preview when the per-session cache (populated by Plan 35-01/35-02) has the target address; otherwise `Blind sign — no ABI available`.

Fixture P anchors the escape-hatch payloadFingerprint as a hardcoded 0x... literal in `test/signing-fingerprint.test.ts`. Persona-cycle integration test re-anchors from-independence across personas.

The `payloadFingerprint` shape is the standard PREP-03 envelope — NO escape-hatch-specific carve-out. The bypass flag is a SEPARATE record annotation, NOT a fingerprint dimension. FROZEN cryptographic-binding chain (`payload-fingerprint.ts`, `presign-hash.ts`, `handle-store.ts` state machine, `send_transaction.ts` three gates, `fourbyte.ts`) stays byte-identical to origin/main. The ONLY change to `handle-store.ts` is ADDITIVE TYPE SURFACE (two optional fields on `HandleRecord`).

Purpose: Close the v2.4 milestone with the escape-hatch tool. CUSTOM-01 surface. Consumes Plan 35-01's `fetchEtherscanAbi` per-session cache for preview-time decode.
