# Quick Task 260605-0x2: Fix `prepare_uniswap_v3_rebalance` tool-description slippage over-claim

## Problem

The agent-facing tool description for `prepare_uniswap_v3_rebalance` over-claimed slippage
protection. Two strings asserted that `slippageBps` is "applied to BOTH the decrease and the
mint min-amounts":

- `DESCRIPTION` line ("`slippageBps` defaults to 50 (0.5%) — applied to BOTH the decrease and the mint min-amounts.")
- the `slippageBps` schema-param `description` ("Applied to BOTH the decrease and the mint min-amounts.")

The code does **not** match this claim. In `src/tools/prepare_uniswap_v3_rebalance.ts`:

- the decrease (exit) leg sets `decreaseAmount0Min = 0n` / `decreaseAmount1Min = 0n` (~lines 450-451);
- only the mint (re-add) leg applies the floor (`mintAmount0Min/1Min = expected × (10000 − slippageBps) / 10000`, ~lines 452-454);
- the `CHECKS PERFORMED` block already states the truth honestly ("slippage floor disabled at prepare layer — see Plan 33-02 convention").

So the tool description (an agent routing prompt — accuracy is non-negotiable per CLAUDE.md) contradicted both the code and the tool's own CHECKS PERFORMED block.

## Scope (tool-description-only)

- **Edit** `src/tools/prepare_uniswap_v3_rebalance.ts`: correct the two over-claiming strings to state
  that slippage is applied to the **mint (re-add) leg only**, and the **decrease (exit) leg's
  min-amounts are 0** (floor not enforced at the prepare layer; deferred to v2.4.x; see CHECKS PERFORMED).
- **Do NOT** change any encoded calldata, the slippage math, or behavior. No FROZEN files touched.
