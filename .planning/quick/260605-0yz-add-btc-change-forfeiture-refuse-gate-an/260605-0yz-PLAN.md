# Quick Task 260605-0yz: BTC change-forfeiture refuse-gate + disclosure (WR-04 parity)

## Problem

`prepare_btc_send` could silently burn change to miners. When the paired account has
no xpub for change-address derivation (`changeAddress === null`), `changeSats` is folded
into the miner fee with **no change output, no refuse-gate, and no disclosure** in the
PREPARE RECEIPT (`src/tools/prepare_btc_send.ts`, change-handling + receipt assembly).

A real-mode **legacy account** (paired before CR-02 xpub/change-output support) sending a
small amount from a large UTXO would forfeit nearly the entire balance to miners,
silently. The **LTC sibling already guards this** (WR-04): it refuses when
`changeSats > 10_000` litoshi and emits a `CHANGE FORFEITED:` disclosure line otherwise
(`src/tools/prepare_litecoin_native_send.ts`). The BTC tool had neither.

## Design decision (real-mode only)

The vulnerability is a **real-mode legacy account**. In BTC, the no-xpub path is reached in
two ways:

- **Real mode + legacy account** (xpub fetch returns empty) → genuine forfeiture risk → GUARD.
- **Demo mode** → personas carry no xpub *by simulation* (stub pubkeys, no real funds) →
  folding change to fee is a demo artifact, not a real loss → **EXEMPT** (keep rehearsal unblocked).

This differs from LTC (which applies its guard unconditionally) only because LTC has no
xpub/change path at all; BTC distinguishes a real legacy account from a simulated demo
persona. Every existing real-mode test stubs xpubs *present*, so the guard is purely
additive — zero existing-test impact.

## Scope

- **Edit** `src/tools/prepare_btc_send.ts`:
  1. Refuse-gate after change-address derivation: `!demoActive && changeAddress === null && changeSats > 10_000n` → `errEnvelope("INVALID_INPUT", …)` (mirrors LTC error code).
  2. Disclosure in the PREPARE RECEIPT: `!demoActive && !hasChangeOutput && changeSats > 0n` → append `CHANGE FORFEITED: <changeSats> sats (…)`.
- **Edit** `test/prepare-btc-send.test.ts`: add a WR-04 describe block (refuse / disclose / xpub-no-false-positive / demo-exempt).
- **Do NOT** touch FROZEN files, STATE.md, ROADMAP.md, or any other tool. Threshold pinned at `10_000n` sats (LTC parity).
